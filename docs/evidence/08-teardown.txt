27 of 32 resources were gone. The Key Vault, the secret in it and the resource group were not.

The cause was in this repository, not in Azure. The secret was a managed `azapi_resource`.
Resource Manager can create a Key Vault secret, but it has no DELETE for one, so Terraform could
not destroy the thing it had created and stopped with the vault still standing behind it.

## 3. The fix, and proof that it works

`infra/data.tf` now writes the secret with `azapi_resource_action`: a PUT, with nothing to
delete afterwards. `infra/versions.tf` now sets `permanently_delete_on_destroy` for the Log
Analytics workspace, because a subscription-wide check after the second destroy found the
workspace only soft-deleted: still recoverable, logs and all, for 14 days.

Neither change was taken on trust. The vault, the secret and the workspace were created again on
their own, and destroyed in a single pass:

$ terraform apply -target=azapi_resource_action.demo_api_key -target=azurerm_log_analytics_workspace.this

One more thing the subscription-wide check found. Azure creates a `NetworkWatcherRG` resource
group by itself the first time a virtual network appears in a region. It is free and it is not
part of this build, but it was there, so it was removed as well:
`az group delete --name NetworkWatcherRG --yes`.

What is left on purpose: a $10 monthly budget alert on the subscription, and the resource
provider registrations. Neither is a resource and neither can cost anything.
